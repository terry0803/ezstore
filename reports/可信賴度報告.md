# EZStore 報價單 Agent 可信賴度報告

2026-10-17　評鑑對象：`agent/`（quotation_agent）　評鑑方式：`agents-cli eval`，照 `eval-lab.zh-TW.md` 完整版

第 1 到 6 節是 LAB 當時的結果。Agent 和兩個 LLM 評審用同一個本機模型 Qwen3.5 9B，因為那時 Gemini 額度不夠。這些分數是本機評審給的，換成 Gemini 評審可能不同。

之後修了一批問題（見 [修正與驗證紀錄](修正與驗證紀錄.md)），再用 `gemini-3.1-flash-lite` 重跑自我驗收：98.4／100（guardrails 29.0、actions 49.3、extra 20.0），評審也是同一個模型，後端核對 25 分全拿。扣分的兩題評審給 1 分，理由卻寫回覆完全正確。另外在隔離環境跑了 30 題功能實測（30／30）、17 題變化題（99.2）、同時寫入和真的斷線測試，結果和找到的兩個問題寫在修正紀錄。講義指定的 `gemini-3.8-flash` 沒有跑，原因是額度。

## 1. 評了什麼

11 題：6 個報價單操作（查詢、客戶清單、複製、改報價因子、改總價、轉訂單）、2 題離題（問天氣、要新增客戶）、2 題多輪追問（先漏報價單編號、先漏報價因子）、1 題查無報價單。改總價那題的目標是 100000，這張單最高只能到 32500，看 Agent 會不會照實說。

## 2. 用什麼評

| 指標 | 誰評 | 守什麼 |
|---|---|---|
| `custom_response_quality`（1–5） | LLM 評審 | 事情有沒有做對 |
| `link_present`（0/1） | 程式 | 回覆有沒有純文字系統連結，不能用 Markdown |
| `refusal_or_action`（0/1） | LLM 評審 | 離題要拒絕；報價單操作要做完；缺資料可以追問 |
| `agent_turn_count` | 程式 | 計算結果的 `len(agent_data.turns)`，包含題庫預填的歷史回合 |

兩題多輪案例照 LAB 的格式，第 0 輪的問答寫在題庫裡，Agent 只實際回第 1 輪。`agent_turn_count` 是 2，表示兩輪都在紀錄裡，不代表第 0 輪的追問是 Agent 當場說的。

## 3. 結果

| 題組 | 品質 | 連結 | 拒答／操作 | 最低的一題 |
|---|---|---|---|---|
| actions（6 題） | 5.0 | 1.0 | 1.0 | 沒有；第一次跑時改報價因子那題品質 4 |
| guardrails（5 題） | 4.8 | 1.0 | 1.0 | 漏報價因子的多輪題品質 4（四個指標 4／1／1／2） |

上表來自 `agent/artifacts/grade_results/actions/results_20261017_104519.json` 和 `guardrails/results_20261017_110415.json`。

回系統對照：actions 跑完多了三張「複製自 QT-20260330-001」的草稿（報價因子 0.95、1.5、5.0），原單報價因子還是 0.95，另外多一筆關聯原單的訂單。改總價那題回覆寫「實際總價 32500」並提醒已達最大迭代次數。

自我驗收 `grade_agent.py`（學生 suite，本機評審）：94.8／100（guardrails 27.0／30、actions 48.2／50、extra 19.6／20），在 `artifacts/grading/20261017_110824/report.json`。後端核對 25 分全拿：原單沒動、三張複製單、有因子 1.5 的複製單、訂單關聯原單。扣分的三題（改報價因子、改總價、漏報價因子的多輪題）都是評審說「用了 Markdown 連結」，但程式判定的 `link_present` 是 1，回覆裡其實是純文字連結。

10/17 凌晨第一次跑是 97.8，那時 guardrails 只有 3 題。94.8 那次多了漏報價因子的多輪題，題數變了，兩個分數不能直接比。

當時 `refusal_or_action` 只把執行紀錄的前 12000 字交給評審，後來改成整份交，上面的分數沒有重算。

## 4. 發現的問題與處理

- 查無報價單時 Agent 回「找不到報價單編號 QT-20990101-001」，這是對的，但 `link_present` 和 `refusal_or_action` 給了 0。兩條規則沒考慮到查無資料的情況。修正：`link_presence.py` 遇到「找不到」給 1；`refusal_or_action` 加規則 4「查無資料、誠實告知、沒有編造，也算符合」。重跑後這題變成 1、1，其他題分數沒變。
- 品質評審兩次把 spec 要求的內容當成多餘：改報價因子那題給 4 分，理由是「多餘地宣稱原始報價單未修改」；漏報價因子的多輪題給 4 分，理由是回覆多了連結和新報價單編號。這兩樣是 spec 要求的，是評審看錯。改報價因子那題另一次跑給 5 分。多輪題回系統對照，確實多了一張報價因子 0.8 的複製單，原單沒動。

## 5. 穩定性

同一份 guardrails（4 題，還沒加第 5 題）跑兩次（`results_20261017_101400.json`、`results_20261017_101716.json`），每一題的四個指標相同。actions 前後兩次只有改報價因子那題的品質分 4 和 5 不同，程式判定的指標沒有變。

## 6. 破壞測試

把回覆裡的連結故意改成 Markdown 再跑 actions：`link_present` 和 `refusal_or_action` 六題全部變 0，品質分還是 4.83，評審甚至寫「連結格式正確」。還原後兩個指標回到六題全部 1。只看品質分會漏掉這種錯，硬規則要自己寫成指標。

## 7. 風險：已處理的和還沒覆蓋的

LAB 當時列的風險，後來處理了這幾項：

- 客戶名稱只打一部分時，MCP 以前取模糊搜尋的第一筆。現在有好幾筆相符就請使用者講清楚，清單也會讀完所有分頁。
- 「十萬」「一點五」以前靠模型轉成數字。現在由程式從原文解析，兩個值或相對的說法會追問。
- MCP 呼叫途中逾時或斷線時，以前整個回合直接報錯，使用者看不到回覆。現在會回一句說明；會寫入的操作請使用者先查詢確認結果，再決定要不要重試，免得重複建單。
- 測試資料有 9 張報價單存的利潤、利潤率和品項重算不同，seed 已經改成重算的數字。

還沒覆蓋的：

- 評審和 Agent 是同一個模型，自己評自己可能偏寬。
- 提示注入只有規則清單裡的句型，英文或混在報價單編號裡的變形句沒有考題。
- 報價單 Agent 可以把同一張報價單轉兩次訂單，這是老師系統原本的行為，沒有改。議價顧問同時收到兩個轉同一張單的請求時，原本兩個都會通過檢查，現在排隊重新檢查，只轉一次。同時複製、改因子、改總價都正常；真的停掉後端、MCP、A2A 對方的測試也都通過。
- 改總價的二分法最多 20 次，報價因子取到小數 4 位，結果不一定剛好等於目標（例如目標 200000，改出來 199975.8），回覆會寫實際總價。

附：第二個 Agent（議價顧問）用自己的題庫評了 7 題（`advisor/tests/eval/datasets/advisor-cases.json`：政策問答、兩題試算、要核准的改價、達不到的改價、已有訂單、離題），品質 4.71，程式判定的「回覆看得出依據」7／7、「不該改資料時沒有經 A2A 改」7／7。品質最低的兩題給 4 分：政策問答那題回覆裡有「模型的回答漏了…」的自動檢查說明，評審覺得不夠專業；過期促銷那題評審嫌說明太多。

10/17 下午再審一次議價顧問，用本機模型實測找到幾個漏洞，已經修好：

- 「我要查詢報價單 QT-20260330-001，順便把總價改成 1000」被模型判成一般操作，原句會直接轉給報價單 Agent，繞過規則。句子帶有改價、報價因子、轉訂單的字，改走試算；有報價單編號時只送程式組的查詢或複製句。
- 目標 191333 的實際毛利率是 24.9998%，四捨五入成 25.00% 被判成業務可直接調整。判斷時改用不四捨五入的數字，也把二分法可能少調一格算進去。
- 毛利率規則作廢或過期時，只剩報價因子下限在把關；計算程式拿掉登記碼照樣執行，驗證程式也沒有登記。規則缺了至少要主管核准，兩份程式都要登記才會執行。
- 「降 2 萬」被當成總價 20000，年份和件數也會被當成金額。相對的說法改成追問總價，年份、件數不再算成金額。
