# EZStore 作業修正與驗證紀錄

2026-10-17

## 改了課程提供的元件

講義要求不改 `backend/`、`frontend/`、`mcp_server/`。檢查時找到幾個會讓 Agent 出錯的地方，使用者同意後才改。

| 元件 | 原本的問題 | 改成 |
|---|---|---|
| backend | 報價因子 0 或負數、訂單單價負數、訂單關聯別的客戶的報價單，都能存進去 | 存檔前檢查，不合法就回錯誤 |
| MCP | 客戶名稱模糊搜尋直接拿第一筆；客戶清單和報價單清單只讀第一頁；NaN、無限大能當參數 | 名稱有好幾筆相符就請使用者講清楚；讀完所有分頁；只收有限數字 |
| frontend | 中文輸入法選字按 Enter 會把訊息送出；成本 0 時利潤預覽算錯；Vite 開發模式沒有代理 Agent；Agent 重啟後舊 session 失效就一直出錯；報價因子輸入框只能填到小數 2 位 | 修正；session 失效時重建一次再送；輸入框改成小數 4 位 |
| seed | 9 張報價單存的利潤、利潤率和品項重算不同，其中 1 張連總價也不同 | 改成重算的數字；定價、成本、數量、報價因子沒動 |

MCP 有一項改了又改回來。改總價做不到的目標，一度改成在複製前就拒絕。這跟講義寫的流程不同（先複製再改，照實說最多到多少），評分程式也要求至少 3 張複製單、回覆要有「未修改」和「實際總價」或「注意」。所以改回原本的二分法流程，只留有限數字的檢查。

主資料庫修正前有備份：`artifacts/fix-20261017/ezstore-before-fix-20261017.dump`（PostgreSQL custom dump）。

## Agent 的修正

報價單 Agent：

- 報價單編號和數字一律從使用者原文抓，模型抽到的值不直接用。「十八萬」「18萬5千」「從 0.85 改成 0.9」都抓得對。一句有兩張單、兩個目標值，或是「降兩萬」這種相對說法，就追問。
- 「修改客戶的報價單」以前被當成要改客戶資料而拒答，修好了。
- MCP 呼叫途中逾時或斷線時，以前整個回合直接報錯、沒有回覆，現在會回一句說明。MCP 錯誤前面的英文前綴（Error executing tool…）拿掉，只留中文原因。
- 實測找到：改總價二分到一半後端斷掉時，複製單其實已經建好，Agent 卻只回「操作失敗：後端服務逾時」，使用者很可能直接重試。現在會寫入的操作遇到逾時、連不上、後端 5xx，回覆會多一句「可能已經建立了新的報價單或訂單，請先查詢確認」。
- 實測找到：`gemini-3.1-flash-lite` 把沒給編號的「我要查詢報價單」判成離題，直接拒答，講義 1.9 要求的是追問。評分題庫的多輪題把第一輪寫死在題庫裡，所以評分沒抓到，是 30 題實測抓到的。分類提示詞補了一條規則；路由也加一道程式判斷，模型判成離題、但句子明確是六種報價單操作之一（沒有刪除、新增、發佈這類字）時，照關鍵字改判再追問。

議價顧問：

- 經 A2A 改價之後，從後端重讀原單和新單，核對客戶、品項、數量、總價，也確認原單完全沒變。轉訂單也一樣核對。
- 規則問答直接由程式照條目的 frontmatter 寫出每一級門檻和核准的人，不呼叫模型，省一次額度。
- 單號格式錯、一句有兩張單，改成追問（「降兩萬」這種相對說法 10/17 下午就已經會追問）。
- 同時寫入測試找到：兩個人同時請議價顧問轉同一張單，第一次檢查都會通過，結果建立兩張訂單，違反它自己「已有訂單就不轉」的規則。現在同一張報價單的轉訂單排隊一個一個做，輪到時重讀報價單和訂單再判斷一次，還能轉才經 A2A 送出。只在議價顧問跑一個容器時有效。

評鑑規則：`agent/tests/eval/refusal_or_action.py` 以前只把執行紀錄的前 12000 字交給評審，改成整份交。

## 模型

講義指定 `gemini-3.8-flash`，程式和 Compose 的預設值維持這個。測試時本機 `.env` 設 `gemini-3.1-flash-lite`，這是帳號能用的模型裡最便宜的（每百萬 token 輸入 0.25 美元、輸出 1.50 美元）。`gemini-2.5-flash-lite` 更便宜，但對新帳號已經停用，呼叫回 404。免費額度的上限要到 AI Studio 看；之前 3.5-flash-lite 遇過一分鐘 15 次的上限，連續跑的時候每輪隔幾秒比較保險。

自我驗收跑了三次才有效。第一次用老師的 `scripts/grading/eval_config.yaml`，`refusal_or_action` 的評審要連 Vertex AI，本機只有假憑證，每題都回 `invalid_client`，分數 81.2 不算數。第二次改用 `local-grading/` 的本機評審版（評分規則和老師的提示詞一字不差），評審程式的 `genai.Client()` 沒存成變數，請求送出前連線就被關掉，分數 65.2 也不算數。修好之後第三次才是上面的 98.4。

離線測試把模型換成假模型，也擋掉對外連線。早先的測試替身沒有換到 Workflow 實際執行的模型節點，所以 10/17 下午報告裡的「73 個離線測試」不能證明完全沒有連網。現在的 159 個是修正後重跑的。

更早用 `gemini-3.5-flash-lite` 跑過同一套 30 題（`artifacts/fix-20261017/gemini-full-acceptance.json`），那時 MCP 還是「複製前拒絕」的版本。改總價做不到那題的預期已經改成講義的流程，上面的 30／30 是新版重跑的結果。

隔離環境用 `artifacts/fix-20261017/compose.test.yml` 改成 Gemini（金鑰從環境變數帶入，不寫進檔案），是另一個 Compose 專案和另一顆資料庫，每項測試前先灌 seed，不碰主資料庫。

## 還沒處理的、測不到的

- 報價單 Agent 可以把同一張報價單轉兩次訂單。這是老師系統原本的行為：資料表沒有限制，講義範例甚至轉草稿；老師的評分程式用 `--runs 2` 時也會在同一份資料上轉兩次，擋下來反而會扣分。「已有訂單就不轉」是議價顧問的示範規則，只在議價顧問那條路上擋。
- 教師私下的題庫拿不到，用上面 17 題變化題替代，不保證涵蓋私下題庫的所有題目。
- 提示注入只測了清單裡的句型和一題「忽略之前的指示」，英文、混在報價單編號裡的寫法沒有題目。
- 評審和被評的 Agent 用同一個模型，評分可能偏寬。
