更正「老師雲端缺 GCP／ADC」的說法

前次把工具的雲端評分路徑稱為「教師正式雲端評分」，不夠準確。講義第 10 頁允許 AI Studio API key，GCP／Vertex AI 是可選方式；第 17 頁說明助教用私有題庫在本機評分，未要求學生購買雲端服務。

名詞在這個專案的意思
GCP projectGoogle Cloud 的專案識別，用於指定雲端服務所屬專案、權限及配額。
ADCApplication Default Credentials；Google 函式庫尋找身分憑證的機制，讓程式代表已授權的使用者或服務帳號呼叫雲端服務。
Gemini API key目前 Agent 透過 AI Studio 路徑呼叫 Gemini 使用的金鑰；持有 key 不表示 CLI 已配置專案及雲端認證。

目前安裝的 agents-cli v1.10.0，對老師設定的 refusal_or_action prompt 指標會走雲端評分服務，cmd_grade.py:245 先要求解析 project。本次直接錯誤是 Could not determine GCP project；標準本機 ADC 檔也不存在，但尚未走到雲端權限、API 啟用或計費驗證，不能說是已收到 ADC 驗證失敗。

所以：Agent 使用 API key 對話與「此 CLI 指標呼叫雲端評分服務」是兩條路徑。沒有配置後者不表示 Agent 不能運作，也不表示作業必須部署到老師的雲端。本地自評與助教正式成績應持續分開標示。
