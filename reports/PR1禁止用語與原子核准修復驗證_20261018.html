兩項 P1 已修正，離線回歸、隔離 PostgreSQL 併發及真實 A2A 串接測試通過。四個本機服務已更新，原有業務資料未變。

1. 禁止用語在補救與待補操作前攔截

兩個 Agent 共用相同規則，補上「不能、不可以、不可、不准、禁止、不許、不允許、不得」及簡體變體。即使模型分類成 off_topic、provide_info 或寫入操作，禁止語句仍不會進入 MCP；待補操作與顧問上一輪試算授權也會清除。單獨回答「不能／不准／禁止」會取消待補操作。

保留正常客氣請求「能不能把…」「可不可以把…」；既有唯讀狀態查詢、否定動詞、保留原單及複製補件回歸仍通過。這是保守的程式判斷，不是所有自然語言均已涵蓋的保證。

2. 把核准版本綁到真正建立副本的交易

  1. 顧問通過 attested computation 與政策後，保留核准時的完整報價快照、目標、實際預測因子、總價及利潤。
  2. A2A 使用結構化版本封包，第一個 Agent 在模型分類前解析並原樣交給 MCP；格式不符直接拒絕。舊版 Agent 的 card 或 MCP schema 不支援時，不降級成普通改價。
  3. MCP 以原有 20 次二分法及逐項單價捨入重新核對候選結果，呼叫新增的 POST /quotations/{id}/approved-price-copy。
  4. 後端在同一筆交易鎖定來源報價、客戶及產品，核對來源 updated_at、內容、明細、客戶等級、產品成本及牌價，重算最終總價與利潤。全部一致才建立最終草稿；版本或結果改變回傳 409 / APPROVAL_CHANGED，完全不新增副本。

第一個 Agent 一般改價仍保留老師原先的先複製與二分法更新流程。六個 MCP 工具與六個 A2A skill 不變；只有顧問附帶核准快照時採用原子建立最終副本的路徑。核准版本是資料前提條件，不是登入認證或主管電子簽章。
