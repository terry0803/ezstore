四項資料與轉單修復驗證

2026-10-18｜對應再次審查 R1–R4

四項已確認問題已修復，測試通過後更新本機服務。原有 15 位客戶、20 項產品、12 張報價、10 張訂單的完整 API 內容比對一致；隔離測試服務已停止。

問題修正與結果
R1：已刪客戶／產品被舊更新恢復改用只更新有效資料列的 UPDATE，禁止 Save 的自動新增 fallback，保留零值及空字串更新，且不回寫舊刪除／建立欄位。兩種操作先後皆驗證不會恢復資料；正常清空欄位與金額歸零仍可儲存。
R2：一般刪除造成訂單來源報價失聯一般刪除在取得報價列鎖後檢查有效訂單；已關聯回 HTTP 409 與中文原因。建立／重新連結訂單與刪除的兩種先後順序均通過。訂單已刪除時，未被其他訂單關聯的草稿仍可刪除。
R3：MCP 發送前失敗導致轉單持續被擋工具發現階段連線失敗或缺少工具時，第一個 Agent 回明確的「未送出操作」。顧問解除該次紀錄，且不再誤報寫入核對失敗。使用實際函式與 SQLite 日誌、替身 MCP／A2A／後端驗證兩種恢復路徑：各建立一次，後續重複轉單仍被攔截。已送出後逾時／斷線保護保留。
R4：清單連按複製造成多次請求與跳頁同步互斥加上按鈕停用，防止 React 更新畫面前的連按；離開清單後的舊回應不再導航。瀏覽器確認只送出一次、其他草稿內容不被切走、失敗後可明確重試。

本輪驗證

  • Agent 464、Advisor 407、MCP 35、scripts 17，共 923 項 Python 測試及 4 個子測試通過。
  • 56 項 Chromium Playwright 測試通過；前端編譯與 Go 測試、go vet 通過。
  • 新增 11 項真實 PostgreSQL 測試、既有 7 項副本清理回歸、4 項 MCP 故障注入通過。
  • 2 項跨 Agent 恢復測試使用替身服務和真正的 SQLite 紀錄；不是 Gemini 實測。本輪未消耗 Gemini 或本地模型額度。
  • 本機後端、前端、兩個 Agent 的映像 ID 與通過測試的映像一致；部署前正式轉單日誌為 0 筆，沒有清除不明寫入紀錄。

範圍

依使用者授權修復，老師基底檔案仍有已記錄差異；新增的客戶／產品 repository 修正已列入允許清單。授權清單通過不等於老師同意修改。這些結果確認本輪四項問題及已測情境修復，不是對整套系統的零 bug 保證。
